# Windows 代理守护：手动关闭后的恢复

## 故障与修复范围

Windows 设置页关闭代理时，不一定只修改启用开关，还可能清空地址、改写绕过项及连接数据。
旧逻辑要求当前有效状态等于原状态，或完整快照等于接管后的确认状态，因此拒绝用户已关闭的代理。

新增完成路径只适用于原为直连、接管已确认的所属会话：当前有效状态及类型值均直连，PAC/策略
未变，持久记录完整匹配，二次回读稳定，才清除本次恢复记录并释放租约。保留当前全部设置，
不调用系统代理写入、类型值还原或通知。常规停止仍按既有精确基线恢复。

## 证据与边界

- 修复前，隔离会话测试重现 `external change or interrupted unknown apply; refusing restoration`。
- 真实 Windows 只读核验确认：原为直连、接管已确认，当前有效直连且 DWORD 开关为零；
  地址已清空、绕过项不同，PAC 为空，受保护策略与基线相同。没有输出原始个人配置。
- 会话回归覆盖手动关闭、停用字段变化、再次接管/停止、遗留 owner 匹配、清理失败重试、
  持久记录冲突及恢复过程中重新启用代理；拒绝外来基线、PAC/自动检测、策略变化、无效开关、
  未确认接管。新增成功路径断言全局写入次数不增加，用户设置逐项保持不变。
- `lanpath-client` 会话定向回归：20 项通过。根 workspace build 与完整 Rust 门禁通过，
  其中 client 单测 699 项通过、1 项既有真实核心测试默认忽略；Tauri host strict Clippy 及
  Android Rust target check 均执行，Android 保留既有两项脚本条件编译告警。
- 独立 GPUI Linux fmt、strict all-target Clippy、7 项守护协议/通信回归与 build 通过。
- Windows 原生系统代理定向回归 27 项通过（包括上述会话场景与隔离文件锁）；GPUI fmt、
  strict all-target Clippy、7 项守护协议/通信回归和 debug build 通过，更新开发镜像调试产物。
- 本轮不修改当前 Windows 代理，不清理真实恢复记录，不停止运行中的已安装程序。
  隔离后端回归和原生编译不代表当前旧 GUI/守护已被热更新，也不代替真实全局接管验收。
