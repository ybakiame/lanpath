# Lanpath NSH Desktop 产品与交互设计

## 1. 产品判断

Lanpath 的主路径是：**准备订阅 → 校验配置 → 启动核心 → 选择策略 → 观察真实流量 → 安全恢复**。

界面服务于这条路径，不按内部模块堆叠页面。每个区域都回答四件事：当前对象是什么、处于什么状态、下一步能做什么、失败后如何恢复。

设计原则：

- 真实状态先于装饰：没有节点缓存、核心未选中、端口冲突、代理需要恢复时，直接指出原因和动作。
- 主任务先于功能数量：启动、停止、当前订阅与实际策略出口始终是视觉焦点。
- 渐进披露：常用操作直接可见，低频操作进入菜单，复杂诊断进入详情。
- 面向桌面效率：紧凑但可读，支持键盘、窗口缩放和长文本，不把触屏布局放大到桌面。
- 可恢复的一致性：保存、取消、刷新、启动、恢复使用同一对象和结果词汇，不制造“已成功”的假象。

目标平台先为 Windows 桌面。后续 Android 复用信息架构和领域语义，但不把桌面窗格直接缩小为手机布局。无 TUI 目标。

概览不是数据宣传页。它把当前真正可执行的下一步置于首位：

未配置时，首屏改为按顺序列出“添加订阅 → 刷新节点 → 选择核心 → 校验启动”，只高亮当前可执行的一步。已有配置时不显示教程。

## 3. 页面与交互设计

### 3.1 订阅

- 列表行固定为：启用开关、名称、当前生效标记、节点数/格式、刷新状态、更多菜单。
- 常用动作“刷新、编辑、原文、设为生效”直接可见；导出与删除进入更多菜单。删除必须确认，且同时说明本地缓存会移除。
- 编辑使用中型弹窗，保留名称、URL、User-Agent 与覆写绑定。刷新不提交未保存草稿。
- 节点信息包括名称、协议、延迟与 UDP 支持。未测速显示“未测”，超时显示“超时”，不得混用。
- 节点和分组用稳定 UUID 作为身份；显示名称、翻译和排序位置都不是身份。
- 分组按“组 → 当前选择 → 可达叶节点”呈现，嵌套选择链清晰可展开。自动策略只展示实际证据，不把自动选择说成用户固定选择。

```text
订阅                                   [新增订阅…]
 东京专线     当前生效   12 节点   [刷新] [编辑] [原文] [更多 ▾]
 新加坡备用   已停用      8 节点   [刷新] [编辑] [原文] [更多 ▾]

 Proxy 组
   自动选择 → 香港 01
   备用     → 新加坡 02
   [测速当前组] [搜索节点…] [排序：原序 ▾]
```

### 3.2 代理策略

- 顶部依次是路由模式、当前组、搜索、排序与组测速。组切换不重置搜索。
- 选中节点使用填充和勾选标识；焦点框只表示键盘焦点，不表示实际出口。
- Selector 允许明确选择；URLTest、LoadBalance、Fallback 显示自动结果；Score 只展示有界的证据摘要、待验证状态和原因，不暴露内部实现术语。
- 模式写入与运行中同步分开反馈：“已保存”不等于“已同步到核心”。同步失败保留已保存值并明确提示。
- 测速只由显式操作触发，结果按原始节点身份关联；列表刷新、排序或过滤不丢失正在测速状态。

### 3.3 连接与流量

- 第一行是活跃连接、上传、下载及速率；第二行才是筛选与详情。
- 历史图使用上传/下载两条线，颜色来自 `chart-upload` / `chart-download`，同时提供图例和文本摘要。
- 连接表按协议、来源、目标、出站、流量筛选；详情显示捕获时的选择链和规则，不以当前配置重写历史。
- 无样本、首次采样、不可见范围均显示为破折号或“暂不可见”，不补零。
- 表格使用虚拟化列表；筛选、排序、滚动位置与选择状态独立保存。

### 3.4 核心

保留当前库存、运行和系统代理三个区域：

- 库存：核心类型、通道、本地/远端版本、选择与删除。运行中禁止修改文件。
- 运行：明确先进行真实二进制配置校验，再启动 loopback mixed 与 Clash API；显示阶段、错误与停止回执。
- 系统代理：显示未接管、本应用持有、需要恢复。接管前的一次性确认，不持久化授权。
- 恢复入口只处理本应用记录，不覆盖未知代理。失败恢复可以重试，不把进程退出当作网络已恢复。

### 3.5 覆写与结构化配置

- 覆写模板编辑分本地 YAML、本地 JS、远程 URL 三个区域；大文本使用多行编辑器，保存栏固定。
- 删除被引用模板先拒绝并指向订阅绑定；未保存关闭需要确认。
- sing-box 分区为网络、DNS、出站、路由与缓存、规则、预览。切换分区保留草稿，启动前统一校验。
- Mihomo 只提供订阅配置合成、预览、校验和运行，不显示 sing-box 编辑器。
- 预览文本可选择、滚动和查看错误。未经二进制校验时，明确标为“合成预览”。

### 3.6 规则与 DNS

路由规则使用可比较表格而非卡片墙：

| 优先级 | 条件 | 出站 | 终结 | 状态 |
| --- | --- | --- | --- | --- |
| 拖动排序或上移/下移 | domain、IP、port、pname、source | 组 / direct / block | must 或继续 | 启用/停用 |

- 同优先级保持源顺序；`must`、`block` 的终结含义在编辑器和运行摘要中保持一致。
- 条件内为 OR，条件间为 AND，否定覆盖整个条件。编辑器不把复杂条件简化为普通域名规则。
- 规则集单独管理来源、格式、更新间隔、校验结果和缓存；更新失败保留上一可用版本。
- DNS 分上游、请求规则、响应规则、缓存与诊断。上游明确 UDP/TCP/DoT/DoH/DoQ/DoH3、地址、SNI 与出站。
- 缓存命中、刷新、过期、失败和清空分别反馈，不把“清空缓存”说成“清空路由事实”。

### 3.7 请求设置

- 四种模式：直连、跟随系统、自定义、核心代理。
- 自定义 URL 只在自定义模式可编辑，其他模式保留供切回；错误不得泄露凭据。
- 核心代理只使用已保存的 mixed 端口，不借用现有监听。
- 设置保存后用于下一次订阅或资源请求，不回写当前核心配置。

### 3.8 脚本与资源

- 卡片显示类型、方言、启停、更新间隔、组成数量与最近结果。
- 编辑分配置片段、关联 JS、配套图标与更新计划；缺失绑定不能保存。
- 间隔采用正整数加秒/分钟/小时/天，保留特殊秒数，避免重复更新任务。
- 更新中保留旧缓存和旧列表，失败提示具体资源与下一步。

### 3.9 MITM

- 使用“主机规则 / 请求记录”分区；CA 安装和移除是独立操作，不在进入页面时修改信任。
- 主机声明、参数和启停只影响下一次启动，不热替换当前会话。
- 请求记录只在运行且分区可见时读取，切换到其他页面后停止。
- 证书路径、指纹、信任范围和回执收进详情折叠，默认只显示信任状态与安装/移除。

### 3.10 备份与恢复

- 导出密码只掩码展示，预览只含摘要，不显示解密正文。
- 选择文件、错误密码、过期预览、确认恢复、待重启、恢复完成是连续状态，不跳转无关页面。
- 恢复前明确停止核心与系统代理；准备后锁定业务修改，重启后确认恢复结果。
- 回滚文件保留，取消或失败不留下“已恢复”的假象。

## 4. 视觉系统

### 4.1 品牌方向：循径而行，径达悠远

视觉强调“路径”而不是“网络星球”：稳定的侧栏、连续的工作路径、清晰的当前位置和返回路径。默认风格是精确、安静、偏冷色的专业工具，不使用营销横幅、装饰渐变或大面积插画。

默认浅色取淡紫白分层，深色取中性紫灰分层。浅色背景保持明亮，避免低对比脏灰；深色避免纯黑压住所有边界。

### 4.2 默认语义色板

| 语义 | 浅色 | 深色 |
| --- | --- | --- |
| background | `#F4F5FA` | `#1D1E2A` |
| card | `#FCFDFF` | `#262736` |
| foreground | `#26243A` | `#EEEEF6` |
| primary | `#5266D6` | `#A7B8FF` |
| primary-foreground | `#FFFFFF` | `#1C2238` |
| muted-foreground | `#62677C` | `#A9ADC0` |
| border | `#D8DCE8` | `#424459` |

主题文件继续补齐 `secondary`、`accent`、`input`、`ring`、`popover`、`destructive`、`warning`、`success`、`chart-upload`、`chart-download`、`sidebar` 及对应 foreground。展示代码只消费语义 token，不写颜色值。

每个控制的状态 token 成对定义：normal、hover、active、selected、disabled、invalid。强调色只用于当前选择、主要提交和焦点，不用于普通说明。

### 4.3 多主题

提供 13 组命名主题，均有完整浅色/深色配对，而不是仅替换一个强调色：

- amethyst（默认）、indigo、ocean、forest、sand、rose、graphite、cyan、orange、teal、crimson、gold、slate。
- 每组定义背景、表面、主文字、主色和状态色；语义状态（错误、警告、成功）不被主题色取代。
- 主题色样是用户数据，可以显示为圆点；圆点周围仍使用语义边框、选择与焦点。

外观页使用 4 列主题网格，窄窗口降为 2 列：

```text
外观
 主题
  ┌ Aa ──────┐  ┌ Aa ──────┐  ┌ Aa ──────┐  ┌ Aa ──────┐
  │ ●●●●●●●  │  │ ●●●●●●●  │  │ ●●●●●●●  │  │ ●●●●●●●  │
  │ amethyst │  │ indigo   │  │ ocean    │  │ forest   │
  └──────────┘  └──────────┘  └──────────┘  └──────────┘

 外观模式       [跟随系统] [浅色] [深色]
 界面缩放       75% 100% 125% 150%
 窗口材质       [亚克力] [实色]
 背景不透明度   20% ───────────── 100%
 界面语言       [跟随系统] [简体中文] [English]
```

> 注：界面缩放/材质为设计目标；NSH 0.5.0 无应用级缩放 API，阶段 0
> 只读展示系统文本缩放，不提供不生效的缩放控件。

- 指向主题时全窗即时预览；离开后回到已保存主题。点击立即应用并保存。
- 已选主题同时显示名称与勾选，不能只靠边框区分。
- 材质与不透明度独立；纯黑模式强制不透明。亚克力只作用于背景，不降低正文表面可读性。
- 主题预览不能导致重复提交或反复创建运行时。

### 4.4 字体、尺寸与圆角

- 界面文字使用系统 UI 字体；代码、配置、节点 ID、快捷键和对齐数字使用系统等宽字体，不下载字体。
- 页面标题 28，分区标题 20，正文 16，辅助文字 14，元数据 12；同屏不超过四种字号和两种字重。
- 标准按钮高 32，工具按钮高 28，输入框高 40，列表行高 36；紧凑只用于桌面数据区。
- 圆角层级：大表面 8pt，普通控件 6pt，小标签/图标 4pt；弹层 8pt。全圆只用于开关、圆点和圆形图标按钮。
- 布局以 4pt 为步进，分区间距 24，分组间距 16，相关控件间距 8，图标与文字间距 4。禁止按截图逐点微调。

### 4.5 窗口与对齐

- 默认窗口 1180 × 800，最小 960 × 640，均为逻辑尺寸；界面缩放支持 75–150%。
- 侧栏宽 208–216，内容区使用剩余空间。窗口窄时先收起次要文字，再折叠低频操作，最后滚动具体内容区域。
- 每页固定少量对齐轴：标题/内容左缘、标签基线、状态列、数值右缘、操作列。行内缺失图标不得改变其他列位置。
- 滚动条属于实际滚动区域右缘。页面整体不为了长表单频繁滚动，只有列表、编辑器或内容超出时滚动。
- 正文不强制 80 字符限制，但长错误与 URL 使用选择、换行或只读详情，不能撑破窗口。

## 5. `ui` 组件层

先在 `src/ui/` 建立应用组件库，再迁移功能页。基础组件包括：

- `Icon`、`Button`、`IconButton`、`Input`、`Textarea`、`Field`、`Switch`、`Checkbox`、`Radio`、`Select`、`Tabs`。
- `Menu`、`Popover`、`Tooltip`、`Dialog`、`AlertDialog`、`Sheet`、`Toast`。
- `Surface`、`Badge`、`Separator`、`Empty`、`Skeleton`、`Spinner`、`ListItem`、`DataTable`、`Toolbar`、`StatusBar`、主题预览块。
- 统一 `size` 与 `variant`，状态由组件内部 token 驱动。功能页只传业务语义、内容与事件，不传颜色、圆角或局部字体。
- 组件必须有 normal、hover、pressed、focus-visible、selected、disabled、loading、invalid 状态，图标按钮必须有可访问名称。
- 建立只用于开发验收的组件画廊，覆盖全部 variant、size、主题、系统缩放场景与 reduced motion；不作为用户导航入口（`--ui-gallery` 启动参数进入，独立于应用根组件）。NSH 0.5.0 无应用级缩放 API，画廊无应用内缩放控件，缩放验收指系统缩放下的可读性。

## 6. 国际化

### 6.1 语言与资源

- 首发支持 `zh-CN` 与 `en`，结构预留 `zh-TW`。默认跟随系统，用户可显式选择并保存。
- 文案集中在 `locales/`，使用意图稳定的 key，例如 `subscription.refresh`、`core.start.failed`、`proxy.recovery_required`。
- 使用 `t!` 读取翻译，根组件注入 `translations_json`。语言切换使用 `set_locale`，跟随系统时传 `None`。
- key 按对象与意图组织，不以中文句子、页面坐标或可变列表索引命名。
- 业务 UUID、协议名、主题 ID、存储 key 与测试 ID 不翻译。翻译后的显示名不参与匹配。

### 6.2 自然语言与格式

- 中文使用“订阅、当前生效、校验并启动、恢复、刷新、原文、覆写”；英文使用对应自然短语，不逐词硬译。
- 错误先说明发生了什么，再给恢复动作，不输出内部锁名或实现层路径作为用户主文案。
- 数字、日期、时间间隔使用 NSH 的 locale 数据与 `Intl`，不手写日期格式或拼接复数。
- 句子不拆成翻译片段。语序、标点和必要上下文由每种语言独立决定。
- 布局使用 start/end 语义，为将来的 RTL 预留镜像能力；快捷键按平台显示 Command/Ctrl。

### 6.3 文案验证

- 验证中英文切换立即生效，主题和当前运行任务不重建。
- 检查英文约 1.5 倍文本长度、长节点名、长 URL、150% 缩放和错误详情，不裁掉恢复动作。
- 所有操作名称与屏幕阅读器名称一致；状态不能只靠颜色或动画表达。

## 7. 动效清单

动效只解释变化，不用于制造氛围。统一 token：

| Token | 值 | 用途 |
| --- | --- | --- |
| instant | 120ms | hover、颜色与透明度 |
| fast | 180ms | press、按钮和选择状态 |
| base | 240ms | tab/侧栏选择、glyph 切换、菜单退出 |
| slow | 360ms | 菜单、弹窗、对话框进入 |
| slower | 500ms | 页面首次列表进入 |
| distance | 4 / 8 / 16pt | 标签、弹层、页面内容 |
| scale | 0.97 / 0.95 | 普通按钮 / 图标按钮 press |
| easing | ease-out 进入、ease-in-out 移动、ease-in 退出 | 所有过渡 |

| 状态变化 | 设计 | Reduced motion |
| --- | --- | --- |
| hover | 120ms 淡色洗涤，不改变布局 | 立即 |
| press | 按钮缩放 0.97，图标按钮 0.95 | 立即，无缩放 |
| 当前导航/分段选择 | 单个选中背景以 base 滑动 | 立即定位 |
| 菜单/Popover | 从触发点以 slow 淡入并移动 4pt，退出 base | 立即 |
| Dialog/确认框 | 遮罩淡入，内容上升 8pt 并淡入 | 立即 |
| 列表首次进入 | 前 10 行以内错峰淡入，之后不重复播放 | 直接显示 |
| 列表更新/测速 | 原位置更新，不重新播放入场 | 直接显示 |
| 启动状态与图标 | glyph 以 base 交换，状态文本原位更新 | 直接替换 |
| 加载 | 骨架或 spinner，加载完成后淡入真实内容 | 静止或直接显示 |
| 主题预览 | 只更新 token，不播放整窗动画 | 立即 |
| 流量曲线 | 数据点原位更新，曲线不漂移 | 直接更新 |

不使用持续水面、粒子或背景 shader。没有“每个控件都滑动”的统一动画。恢复、错误与危险确认优先可读性，不做庆祝动效。界面不发声。

## 8. 状态、键盘与可访问性

- 页面草稿、选择、筛选和滚动位置由页面或明确的工作区状态持有；核心与代理运行状态由共享运行时持有。
- Tab / Shift-Tab 按视觉与任务顺序移动；方向键处理组内移动，Enter / Space 激活，Escape 关闭顶层弹层。
- F6 / Shift-F6 在侧栏、内容、状态栏间移动；Ctrl+S 保存当前分区；Ctrl+, 打开外观。
- 焦点框始终可见且不被滚动容器裁掉；弹层关闭后焦点回到触发控件。
- 图标只用 Lucide 同一系列；图标按钮必须有可访问名称与必要提示。
- 正文与重要边界目标对比度至少 4.5:1，主题切换逐项检查。状态同时使用文字、图标或形状，不依赖颜色。
- 长列表使用虚拟化，行身份与业务身份一致；回收行不得携带其他节点的局部状态。

## 9. 实施顺序

### 阶段 0：设计基础

- 建立 `src/ui/`、语义 token、动效 token、组件画廊、locales 与主题注册。
- 统一根级外观、语言存储，不先改业务行为。界面缩放为诚实边界：NSH 0.5.0 的 `font_scale` 仅平台可读，阶段 0 只读展示系统文本缩放，不提供存而不生效的选项（见 README）。
- 用组件画廊验收全部主题、明暗、键盘与 reduced motion。

### 阶段 1：主路径统一

- 完成概览、订阅编辑与当前运行摘要共享。
- 统一侧栏、状态栏、启动/停止、当前订阅与实际策略出口。
- 迁移外观页到多主题网格与即时预览。

### 阶段 2：策略与观测

- 完成代理策略、连接与流量、测速和选择链。
- 增加真实运行数据、筛选、历史与可见范围说明。

### 阶段 3：高级配置与工具

- 完成结构化配置、规则与 DNS、诊断、脚本资源与 MITM。
- 保持预览、校验、运行和恢复使用同一数据源。

### 后置事项

- 分发更新与 TUN 另行排期，不进入当前交互实现计划。
- 上述页面为设计目标，未实现的功能不得在界面中提前显示占位按钮或成功状态。

## 10. 验收标准

每阶段都必须保留现有真实业务验证，并新增对应视觉和交互证据：

- 明暗主题及每个主题配色，浅色无脏灰，文字与边界对比度合格。
- 960×640、1180×800、1440×900，以及 75/100/125/150% 缩放。
- 键盘完整完成主路径，检查 Narrator 的名称、角色、状态与焦点恢复。
- 中英文切换、长文本、长 URL、空状态、错误状态、离线与恢复。
- reduced motion 下全部操作仍清楚可用，动效清单逐项验证。
- 代码检查无展示层颜色字面量、无按页私有控件样式、无翻译文本作为业务身份。
- 真实核心、真实端口、系统代理与恢复场景继续单独验收，不以截图代替行为证据。
