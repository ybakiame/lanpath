# GPUI 桌面重设计验收

范围为独立 `apps/gpui` 的窗口、主题、侧栏、配置导航和页面呈现。设计见
[桌面设计说明](../desktop-design.md)。本记录汇总本批交付证据，不保存逐次操作日志。

## 构建与检查

从仓库根进入 devenv，独立桌面执行：

```sh
devenv shell -- cargo fmt --manifest-path apps/gpui/Cargo.toml --check
devenv shell -- cargo clippy --manifest-path apps/gpui/Cargo.toml --locked --all-targets -- -D warnings
devenv shell -- cargo test --manifest-path apps/gpui/Cargo.toml --locked --lib
devenv shell -- cargo build --manifest-path apps/gpui/Cargo.toml --locked
```

Windows 镜像使用既有锁定 Rust 1.98.0/MSVC/SDK/CMake 原生工具链执行同组独立项目检查，
未安装或升级宿主组件。检查按阶段集中执行，局部修复只重跑受影响项：

| 阶段 | 已执行与结果 |
| --- | --- |
| 主题与页面重设计 | 两端 fmt、严格 all-target Clippy、build 通过；Linux 库测试 157 通过 / 5 忽略，Windows 154 通过 / 11 忽略 |
| 外观最终定向检查 | 两端 fmt、严格 Clippy、build 通过；`--lib appearance::` 在 Linux 13 项、Windows 12 项通过 |

## MITM 主机同步与页面整理（2026-11-08）

定位到 MITM 视图仅在创建时读取派生主机，原“刷新状态”和进入页面只查询 CA、监听地址和流量，未重读资源聚合。初版进入页面请求同步，可见时每 6 秒重读资源主机与保存的设置，流量每 2 秒更新（静态轮询已由下一节取消）；手动主机与开关草稿保持，刷新失败保留最后成功的主机快照并显示错误。移除两个手动刷新入口，不热替换运行会话。

页面分为主机规则和请求记录，保存固定在底部。CA 默认只显示信任状态、安装/移除操作和详情入口，路径、指纹、回执、PEM 复制默认折叠；手动主机区折叠并显示条目数。证书详情使用标准按钮补齐可访问名称和键盘入口，窄窗口使用紧凑标题及单行 CA 摘要。

新增两个桌面业务回归：回环服务器提供带 `max-size=-1` 的响应 hook 与 MITM 声明，经真实更新写入 GPUI 缓存后关闭服务器，确认 JS、主机来源、MITM 启动链一致，资源启停影响聚合；只有排除项不会因脚本 URL 表达式而产生包含项或启动 MITM。共享白名单包含项判断也修正派生排除项误计数，并补充回归。

行为实现后，独立桌面两端 fmt、严格 all-target Clippy、默认库测试及 build 通过：Linux 171 通过 / 5 忽略，Windows 168 通过 / 11 忽略。共享 workspace build 和 Rust 门禁通过，client 库 692 通过 / 1 忽略，Tauri host Clippy、Android target check 通过，Android 既有两项条件编译告警保留。后续证书折叠与紧凑布局只补两端定向 Clippy/build，没有重复无关全量场景。

Windows 显式运行既有真实 sing-box MITM 用例：适配夹具先初始化 GPUI 文档，再创建订阅；改用回环远程模块更新派生主机与关联 JS，生成配置经真实核心校验、启动和 HTTP 代理请求后，收到附加的 `-script-ok` 正文并记录流量，核心与 MITM 正常停止。用例通过；此场景不安装 CA、不改系统代理/TUN，不等于本轮重新验收真实 HTTPS 信任与超限响应。

新增可选 [native_mitm_review.ps1](../../apps/gpui/tools/native_mitm_review.ps1)，显式接收 Binary、WindowTools、OutputDirectory，使用隔离根与两次请求的回环模块服务器。Windows 最终 13 项断言通过：无手动刷新入口、CA 默认折叠与详情展开、真实更新报告主机数、进入页自动显示主机及来源、周期同步保留草稿、Ctrl+S 保存、停用后移除派生主机，以及 960×640 / 150% 下保存按钮和主机视口可见。截图复查主机/来源、CA 折叠与展开、请求记录空态及最小窗口；最小窗口主机视口高 104 个物理像素，保存按钮位于窗口内。进程正常退出、stderr 为空。

本轮原生 UI 不启动核心，真实核心证明来自上述单独的业务链路用例；未覆盖所有主题与 DPI、全部 CA 操作和真实超限流量。初轮自动化暴露证书折叠缺少可访问名称、主机行不可被 UIA 读取以及最小窗口主机视口受说明挤占，修正后定向检查和上述场景通过；没有为此重复共享全量门禁。所有夹具、截图和原始日志留在本机产物目录，不使用个人资源，不安装/移除系统信任，不覆盖已安装程序。

## MITM 改为进入时加载（2026-11-08）

按后续反馈取消上节初版的 6 秒静态轮询：配置、派生主机与 CA 状态每次进入页面只加载一次；保存和 CA 操作回写对应结果，核心启停通过带会话代次校验的独立地址查询更新运行状态，不重读配置/CA。请求记录只在核心运行且记录分区可见时每 2 秒读取，切换分区读取一次；相同结果不触发页面通知。

两端定向 Clippy/build 通过，Linux fmt 与 MITM 业务定向 2 项通过；真实核心忽略项本次未重复执行，未重跑共享全量门禁。扩展原生脚本后 Windows 16 项断言通过：只修改隔离夹具的已保存缓存，停留超过原 6 秒周期时主机快照保持不变，重新进入后加载新增主机，两次均保留手动草稿；Ctrl+S、资源停用、CA 折叠、150% 最小窗口和正常退出继续通过，stderr 为空。测试不修改个人配置或系统信任，不启动真实核心，截图和日志仍不入库。
