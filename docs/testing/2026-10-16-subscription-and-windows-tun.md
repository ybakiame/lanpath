# 订阅请求与 Windows TUN 修复验证

## 根因与修改

| 项目 | 参考程序/现场行为 | Lanpath 原实现 | 修正 |
| --- | --- | --- | --- |
| 代理 | 可跟随系统、核心或自定义代理 | 订阅强制直连，忽略既有本地代理选项 | 四种全局请求代理策略，与 GitHub 镜像解耦；四个订阅入口、远程资源与核心下载共用 |
| 压缩 | Go 默认 HTTP transport 自动处理 gzip | 未开启解压，压缩字节被当 UTF-8 | gzip/Brotli/deflate 解压后识别格式 |
| 会话 | 某订阅首次 HTTP 200 HTML 并设置 cookie，短时间再请求返回 YAML | 一次请求后直接解析，无 cookie 会话 | 同一临时 cookie jar 立即重试一次；反复挑战明确报错 |
| UA/超时 | 可配置，默认 UA 为 clash.meta/mihomo | 自定义 UA，默认 clash.meta，30 秒 | 保留现有值；实测两个订阅均兼容，不凭猜测替换 UA |
| Windows 授权 | 提权后的新进程仍显示无权限 | 管理员组 RID 写为 0x22（34），应为 0x220（544） | 使用 SDK 常量生成 S-1-5-32-544，增加 Windows well-known SID 回归 |
| Windows 实例 | 每次授权新增一个窗口 | UAC 成功后原进程未退出 | 正常退出旧实例并沿用退出清理；已有权限时不重复提权 |

## 已执行验证

- 通过本仓 Nix 环境的定向 curl 请求确认：第一个订阅返回 YAML；第二个首次返回 HTML/cookie，第二次携带 cookie 返回 YAML。
- 修正后的 Rust 客户端分别通过显式本地代理和默认环境代理，均成功解析两个订阅。
- 私密地址只置于临时输入，元信息只输出状态、格式与节点数；不将地址、cookie 或订阅内容写入测试/日志/提交。
- 本地 HTTP 回归验证 cookie 挑战两次请求、反复挑战次数上限、401 不重试、重定向携带 cookie、代理与 gzip、错误移除私密 URL，以及既有原文保真。

后续完整门禁记录以实际执行结果和 CI 为准；Windows UAC、TUN 建卡、Android 真机网络仍需设备验收。
不在用户当前 Windows 应用上自动触发 UAC、安装或重启代理。

clippy 与 Android target check；Android debug APK/AAB 构建成功。6 项新增 HTTP 场景与既有订阅测试
