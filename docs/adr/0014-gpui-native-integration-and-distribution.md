# ADR-0014：GPUI 原生系统集成与独立分发

状态：Accepted（架构选择；功能与发行验收另记） · 日期：2026-10-24

## 背景与授权

ADR-0013 第 1–11 单位完成后，用户明确要求继续完成剩余功能、Windows 实测、配置兼容性、
最终 UI 以及 MITM/主流脚本定义与执行兼容性检查。用户说明 Windows 实例已停止、上游代理
由路由器提供，并授权本机系统集成测试。此授权不要求删除旧产品数据、停用第三方资源、
降低 TLS/UAC 安全性或直接发布公开版本。

用户在两项独立选择中明确采纳：窄权限辅助进程；独立 GPUI 身份并行安装。
因此本记录为 ADR-0013 第 12–13 单位提供架构依据，不把测试许可推定为整体 UI 提权或
接替稳定 Tauri 的发行身份。架构采纳不等于功能已实现、平台验收通过或生产切换获批。

## 决定

### 首个非 TUN RC 的范围与恢复进程

用户后续明确将首个 RC 限定为 Windows 非 TUN 功能，优先完成授权与生命周期、用户态网络、
签名升级恢复及 Surge/QX 兼容范围定版；TUN、最终 UI 和真实数据迁移后置。完成验收后合并
主线并本地打包 `0.2.0-rc.1`，不据此自动推送、创建标签或公开发布。

产品元数据 `tun_supported=false` 在启动准入处拒绝已保存的 TUN 选择，保留原值，不静默
改写数据，也不进入受保护代码暂存或提权路径。现有 TUN 实现与证据保留，但不属于此 RC 承诺。

用户明确选择独立普通权限恢复进程，而不是接受 GUI 崩溃后必须重开的系统代理限制：

- 同一映像的窄入口在 GUI/业务初始化前分派，不安装服务或启动项，不执行脚本或接管业务根。
- 守护只继承精确 GUI 查询/等待句柄。父子验证普通 token、SID、会话、登录身份、创建时间、
  映像及 Pipe 对端进程；不依赖 PID/进程名推断所有权。守护须独立于所有 Job，
  不具备独立生命周期或握手未就绪时，在 WinINet 写入前拒绝接管，不静默降级。
- 守护实际持有 session/owner lease，串行完成接管及归还的变更、回读和持久 checkpoint；
  GUI 只发送身份绑定、有界且带序号的 IPC 请求，状态查询也读取守护的实际所有权。
  GUI 死亡或 Pipe 丢失不取消正在执行的变更序列，之后按精确状态恢复；通信超时不证明
  没有副作用，恢复和进程退出未确认时保留核心/MITM。正常归还后守护退出，不安装常驻服务。
- 复用 DPAPI、独占租约、精确类型值及有效状态比较，不覆盖外来编辑或后继 owner；
  既有显式遗留恢复也转由守护执行。只等待原 operation-file 锁竞争，owner lease 仍非阻塞，
  不能通过重试外来/未知状态放宽恢复。未知/未完成恢复保留证据，没有通用注册表写入、
  任意业务路径或额外终止进程的权限。进程中断证据不等同于守护自身故障或断电恢复。
- 已完成接管且基线为直连的会话，用户在 Windows 手动关闭代理后，可能同时改变停用的
  地址、绕过项与连接数据。此时只在持有租约、持久记录完整匹配、有效与类型值均确认直连、
  PAC/策略未变且二次回读稳定时，结束本次恢复占用，保留当前设置；不写 WinINet/注册表。
  原基线为外来代理、未知接管、策略变化或后继 owner 不适用此完成路径，失败仍保留证据。
- 用户态核心的强制停止与原已退出按实际终止操作分类；进程退出、PID 记录清理、系统代理
  归还分别证明。调用成功或退出码不能推导优雅退出；清理失败仍须保留可重试的恢复状态。

以上是已决定的实现契约，不是新增原生验收通过声明；实际非 TUN 网络、故障与升级结果须
在本 RC 集中验证后记录。已有真实 TUN 验收不代替这一轮，交叉产物不代替目标架构原生运行。


### 权限与效果域

- GPUI 窗口、订阅/Profile JS、任务脚本、资源下载、MITM 和业务存储保持普通用户权限。
- Windows TUN 由会话期窄权限辅助进程监督受信核心；不安装常驻服务，不整体重启高权限 UI。
  同一程序的受限子命令须在 GUI、存储与普通重启初始化前分派，不允许退回普通应用路径。
- 本地 IPC 必须具有明确 ACL、拒绝远程、首实例保护、双向实际进程/创建时间/SID 校验及
  有界版本化消息。调用者不能指定任意高权限可执行文件、命令参数、写入路径或控制日志路径。
- 从已验证、产品绑定的签名资源清单确定可信程序/核心；标准目录与便携目录均经明确的受保护
  staging 引导。仅检查路径、版本输出或 UI 自报哈希不构成高权限执行信任。
- Profile 与其他脚本在普通权限下先完成合成。辅助进程独立验证最终配置，把引用资源快照到
  受保护会话目录，不让高权限核心继续读取用户可替换的配置、规则集、证书或面板文件。
- 机器级 TUN 协调、日志与精确进程身份不以每数据根锁替代；优雅退出、强制退出与未恢复效果
  分别报告。没有可靠所有权证据的网卡、路由、DNS 或驱动不得删除。
- 用户 WinINet 系统代理与 CurrentUser CA 操作仍由原普通用户执行，与 TUN 分别许可。
  系统代理采用持久意图、应用/回读、守卫归还与冲突状态；没有会话不得无条件关闭代理。
- 保持 TLS 验证和 UAC；同名证书不是所有权。只按完整证书身份移除本次确实新增的临时信任，
  旧证书及有效旧 CA 身份不自动重建、替换或清理。

### Windows 管理模式核心与参考项目复核

2026-10-25，采用最小受控核心补丁。本地参考实现的调用链为：

- `frontend/src/utils/helper.ts::SwitchPermissions` 设置程序 `RunAsAdmin`；
  `BehaviorSettings.vue::restartApp` 提权重启整个 GUI。
- `bridge/exec.go::ExecBackground` 通过通用路径、参数和继承环境启动核心；
  `kernelApi.ts::initCoreState` 根据 PID 文件及进程名前缀恢复运行标记。
- `bridge/exec_windows.go::SendExitSignal` 使用独立进程组和 Ctrl-Break；
  `exec.go::waitForProcessExitWithTimeout` 超时后强杀，但不提供网络效果恢复回执。

因此复用定向优雅退出的机制，不采纳整体 GUI 提权、通用高权限执行桥或仅凭 PID/名称的
所有权判断。参考实现不替代本项目的辅助进程边界；不复制其源码形成第二套代理核心。

采用锁定 sing-box 源码及最小 Windows 管理模式补丁：明确报告实际创建的适配器身份，
在可产生网络设置前完成辅助进程持久确认，并管理本次防火墙等副作用的生命周期。
不以“预先创建同名适配器”推断官方核心会采用它，也不把强杀或进程消失等同于完整恢复。
源码、依赖、补丁、构建标识、目标架构及最终摘要须绑定 GPUI 自身的可信产物链；
现有 Tauri/Android 不自动切换到该实验产物。

此决定是实现授权，不是已实现或 Windows 行为验收通过的声明。未完成所有权证明时，
保留 `RecoveryRequired` 和日志；不得先清除记录，再在下一次请求中把“没有记录”报为已恢复。

实现与已取得证据（2026-10-25）：

- `apps/gpui/managed-core/source.json` 锁定 sing-box `v1.14.2`、sing-tun
  `ddaa4ca25e3bcb776d6ce81f4477b3becb5426de`、现有 go-winio 依赖、模块校验和、
  归档 SHA-256、Go `1.26.8`、构建标签及协议 `1`；补丁只作用于独立构建副本。
- `tools/managed_core.ts` 已真实构建 x64 Windows 核心，实际执行报告
  `1.14.2-lanpath.1 / go1.26.8 / windows/amd64`；没有有效管理会话的 TUN 实际启动
  在适配器创建前失败。此命令不替代已授权会话的接管与清理测试。
- 应用编译常量及 VERSIONINFO 同时记录同一源码摘要；分发前结构化读取 PE 资源，
  防止旧应用与新核心混包。真实 Windows 应用的 Rust/Bun 摘要一致，
  不同摘要与改动资源均被拒绝，未修改原文件。
- helper 协议升级为 `3`，会话绑定 OS SID 与持久数据根 UUID；核心的认证、
  实际 GUID/LUID/index、应用绑定防火墙意图及完整启动按顺序落盘后 ACK。
  防火墙采用 `INetFwRule/2/3` 全部公开属性的回读与比较，只删除未变化的本次规则；
  COM 不提供 compare-and-delete 原子事务，不宣称抵御另一个并发提权管理员的 ABA 修改。
- 已通过握手乱序/重放/伪造身份回归，以及真实 Windows 上不调用 Add 的防火墙属性采集；
  尚未据此宣称适配器、路由、DNS、防火墙写入和故障恢复已完成原生验收。
- 停止证据限活动适配器、地址、路由、DNS 与本次规则；不承诺卸载驱动包或还原全局
  DNS 缓存。创建已获许可却缺少实际回执、启动进程身份缺失、查询失败或残留时保留记录。
  受保护的 FakeIP 缓存按 SID/根 UUID 隔离，停核后提交；提交失败同样保留会话。

Windows 装载约束单独验收。[应用清单](https://learn.microsoft.com/en-us/windows/win32/sbscs/application-manifests)
不是任意运行目录的沙箱，[DotLocal 调试覆盖](https://learn.microsoft.com/en-us/windows/win32/dlls/dynamic-link-library-redirection)
也不能靠进程启动后的检查反向消除风险。实际 Windows 启动证明清单中的
`preferSystem32Images` 不是已注册的设置：SideBySide 报错并返回 Win32 14001。
已删除该设置；SDK 规范化后的原生程序现可启动，读取的 ImageLoadPolicy 为 0，
不得据此声称具有系统目录优先的启动前装载缓解。

受保护引导改用 Windows 自身的 `IFileOperation` 提权代理，仅逐个复制清单内的固定叶文件。
源文件（包括清单与签名）及全部祖先目录保持句柄租约；不递归枚举用户可写的程序目录。
系统 Known Folder `ProgramFiles` 下的代码缓存按程序 SHA-256 与原用户 SID 摘要隔离，
同一用户/程序的 staging 由跨会话、带明确 SID ACL 的命名互斥量串行化。
复制先落到清单路径派生的 `.lanpath-staging` 文件，验证普通单链接文件、所有权/DACL、
大小和摘要后才改名为最终文件；取消或中断后，仅清理已验证保护目录内的保留传入文件并补齐缺项。
已改变的最终文件、未知目录项、重解析点、硬链接和越权 ACL 一律保留并报错，不覆盖修复。
只有完整签名、精确目录项与所有权/DACL 均通过的代码缓存才允许启动高权限程序。
不得先从用户可写目录提权启动应用；不传播源 ACL，不允许硬链接、撤销、复制钩子或错误后继续。
程序启动后的 `SetDefaultDllDirectories` 只约束后续装载，不替代此前的受保护路径。
真实 Windows 已通过 Program Files 的服务账户所有权和只读继承 ACL 采集验证。
文件操作在专用 STA 线程执行，不改变调用者已有的 COM 模式；实际 MTA 调用最初返回
`0x80010106`，修复后原生复制/改名冲突拒绝、二进制保真及精确叶文件清理通过，
永久 Windows 回归同样通过。普通清理确认仅对已分类的可丢弃叶文件抑制，复制/改名
和 UAC 不共用该标志；不使用撤销或回收站。专用线程的 COM 接口不能跨线程移动。
后续签名 Windows GUI 已完成受保护缓存暂存、旧故障会话恢复、受控启停及 IPv4 直连 TUN
接管的有界验收，具体证据与未覆盖范围见[开发验证记录](../development.md#windows-gpui-实验性并行)。
首次缓存准备仍可能有多次 UAC；复用 STA/Shell 会话不构成 Windows 只询问一次的保证。
授权准备与网络接管计时分开，未完成授权不归类为卡死，也不以移除验证或提权整个 GUI 降低交互成本。



### 独立发行与数据

- 产品显示名为 `Lanpath GPUI`，应用/AUMID 为 `com.ybakiame.lanpath.gpui`，
  分发程序为 `lanpath-gpui.exe`。Tauri 与 Android 的身份、更新链和数据保持独立。
- 2026-10-25，用户明确选择移除 GPUI 安装模式，仅发行同一份签名 ZIP，默认便携。
  程序旁空文件 `lanpath-gpui.portable` 选择 `<exe目录>/data/`；退出后移除标记则使用
  `%LOCALAPPDATA%\LanpathGPUI` 标准目录。切换方法只写入文档，不增加界面切换或依据 cwd 选根。
- 并行期由 GPUI 独占自己的配置目录，Tauri 继续沿用现有标准配置目录；不共享可写根、
  不自动双写，也不为试用 GPUI 搬迁或覆盖 Tauri 数据。正式替换与旧标准目录交接须另行
  执行停机、预览、事务导入与可恢复回退；默认便携不意味着读取、合并或自动切回旧目录。
- 2026-10-25，用户明确选择“私有目录优先”。标准与便携模式的 Windows 数据目录均要求
  文件系统支持持久 ACL，且由当前用户拥有、只向该用户/SYSTEM/Administrators 开放。
  缺失目录在创建时即私有化；只冻结已验证安全的继承 ACL，不自动接管外来目录或修复公开 ACL。
  不支持的卷、外来账户或开放权限明确报错，不静默退回明文便携模式或增加密码存储格式。
  跨账户使用显式导入与重新授权；物理移动同账户 Portable 保留数据根 UUID，不代表跨账户
  继承系统代理、CA 信任或 TUN 控制权。[exFAT/FAT32 无 ACL](https://learn.microsoft.com/en-us/windows/win32/fileio/filesystem-functionality-comparison)
  不属于此数据存储边界。
- 旧实验数据和用户选择的 Tauri 数据只通过明确预览、选择范围、事务导入和可恢复回退进入
  新根；不得为了兼容直接放开实验准入或在读取旧根时运行业务迁移。
- 配置、资源、历史、外观与 CA 身份属于不同迁移类别。配置导入不伪称全数据迁移；
  SQLite 历史须一致性复制，CA/私钥须明确选择。原始源目录不修改、不删除，不静默双写。
- 删除 GPUI 安装器、卸载器、卸载登记、快捷方式注册及安装器专用更新交接；单实例与适用的
  进程级平台适配保留，不冒用另一产品身份，也不以移除安装器消除 TUN 的独立授权要求。
- 独立更新清单、渠道与 Ed25519 验签身份绑定产品、版本、目标架构和文件摘要；两种数据模式
  使用唯一 `gpui-ARCH.json` 和 `-portable.zip`。不接受 setup 产物、Tauri 签名或未验签回退。
  应用只校验和下载；退出后由外部已认证包执行普通权限原生载荷事务，不覆盖运行中的映像。
- 私钥只保留在既有受限签名目录的 GPUI 子目录及明确配置的 CI Secret，不写入源码、日志、
  测试报告或更新清单。源码仅携带真实公钥；签名与 Authenticode 发布者身份明确区分。
- 载荷更新要求完整已认证旧包及更高版本；不提供全新安装事务。共同的 `.gpui-payload-*`
  journal 绑定目录身份、数据模式及便携标记/data 身份；旧恢复状态拒绝自动转换或删除。
  未知文件、便携 data 与外部标准数据根均不属于载荷替换范围。x64、ARM64 的构建、认证与
  原生行为分别验收，不能以一个架构或产物存在宣称另一架构运行与恢复通过。

### 后续 Rust UI 路线（规划，尚未执行产品切换）

- 后续 `0.2.x-rc` 桌面候选只通过 GPUI 专用流程发行，使用 `gpui-v0.2.x-rc.N` 标签；
  标签必须匹配独立 Cargo 版本并标记 GitHub prerelease，不推进 Tauri 或稳定产品的更新身份。
  当前版本不因规划自动升版，也不授予发布权限。Tauri 桌面停止扩展新功能；在 GPUI 的功能、
  数据导入/回退、网络恢复、更新、输入及所需架构通过验收后，才执行桌面链路退役。
- 移动端 Rust UI 是后续候选，不把 GPUI 桌面运行时直接编译为 APK。官方
  [Mobile Guide](https://gpui-kit.com/docs/mobile/) 明示实验性及有限 Android 组件验证，
  [gpui-mobile](https://github.com/itsbalamurali/gpui-mobile) 提供 Android 原生宿主路线；
  当前锁定 GPUI 核心 `0.3.9` 与上游移动平台的 `0.3.6` 尚未对齐，不能直接混用依赖。
- 移动候选优先复用适用的 Rust 业务、现有 Kotlin `VpnService` 和 Go/libbox 单核心，
  将 Tauri 插件包装改为窄 JNI 桥。取消/撤销授权、前后台与 Surface 重建、输入法、文件导入导出、
  VPN fd/路由保护及真机渲染均须验证。此路线不等于同时重写核心或承诺零 Kotlin/零 Go，
  也不自动把桌面 MITM、更新或提权 helper 加入 Android；当前移动壳保持可用。

### 共享进程身份与 macOS 恢复边界

- 经用户明确选择，共享引擎保留 macOS 普通桌面启动及自有子进程停止能力，不因 Windows
  管理核心迁移而让既有 Tauri macOS 启动失败。使用操作系统创建身份和可执行路径识别进程，
  不以调用者时间、名称或单独 PID 作为恢复权限；未知旧记录不自动删除。
- macOS 通过 `proc_pidinfo(PROC_PIDTBSDINFO)` 读取包含微秒的创建时间，完整校验结构及 PID，
  在路径读取前后复核创建身份。仅明确的进程不存在映射为 `NotFound`，权限和其他查询错误
  保留为未证明状态。已持有的 `Child` 仍可停止；自动终止存活孤儿进程暂不提供，
  保留恢复记录并明确报错，不退回存在 PID 重用窗口的 `kill(pid)`。
- macOS 的编译检查不能替代 Intel／Apple Silicon 原生运行、权限与崩溃恢复验收；
  此边界不扩展 GPUI 的发行平台，也不新增强制 CI 门禁。

### GPUI 启动前资源准备

- 经用户选择采用“仅用缓存，保留既有降级”。预览和真正启动在自有核心建立之前准备资源，
  保存的 Core 端口不构成可用性或所有权证明；该策略下不发准备请求、不借用外来监听，
  也不自动直连、启动临时核心或重启当前核心。
- 所选订阅没有可用节点缓存时明确阻止准备，提示用户显式选择其他请求策略或导入缓存。
  远程覆写使用已有缓存；可选覆写、规则缓存缺失仍按既有契约告警降级，而非改成全依赖硬失败。
  手写规则可从已保存内容恢复文件。该策略不重写请求设置，也不改变 Tauri 的现有网络准备行为。
- 其他显式策略使用一份固定的请求快照覆盖订阅、覆写、自定义规则及仍需物化的内置远程规则；
  GPUI 不继续使用旧式内置下载器的强制直连例外。已有 local／inline 定义是有效配置来源，
  不因另一份旧式缓存缺失而删除其引用，也不为未声明的内置项下载或报告缺失。
- 此策略约束应用侧资源准备；仍保留的其他 sing-box 远程规则集遵循核心自身配置与缓存，
  不把本轮应用侧验证宣称为全部核心出站、FakeIP、TUN 或系统代理组合的验收。

### MITM 与脚本兼容性

- 兼容性拆分为格式导入、规则转换、JS 宿主 API、实际 HTTP/TLS/上游路径及任务执行；
  任何一层成功都不能代替其他层的证据。
- GPUI 经用户决定采用 Surge 为主要、Quantumult X 为次要兼容目标；新建、切换与导入仅开放这两者。
  Loon、Stash 仍显示但不可选；嗅探保留真实方言，不能把未开放资源自动标成受支持格式。
  历史记录允许不变方言的编辑，不删除、转换或共享身份。共享层保留既有四种方言的解析/运行能力，
  不改变 Tauri/Android；来源、方言、模块参数、启停、超时、binary/header/body 模式仍须完整保留。
  当前目标为经过验证的公开 HTTP 脚本子集，资源解析器、厂商面板/管理 API 和 WebView 不构成隐含承诺。
- 正则兼容经用户选择采用纯 Rust 有界双引擎：普通表达式保留 `regex` 快路径，必要时使用
  `fancy-regex` 支持的前后向断言等语法；不引入 PCRE2/C 工具链，也不宣称 PCRE 全集兼容。
  导入、缓存恢复、rewrite 与 hook 选择共用 `Pattern`，编译/输入/回溯/替换/输出预算失败均为
  可传播错误；运行调用方终止该交换，不把错误当成未匹配或继续转发部分修改。
- 参数化 MITM 只对已声明参数展开 hostname 键和值，保留原始声明到现有版本化缓存；
  每次激活按当前模块默认值与用户值求解，运行白名单和来源展示采用同一路径。
  禁用键不贡献域名；未解析、控制字符、配置段或证书安全选项注入不激活并给出脱敏诊断。
  展开后的字符串不重新进入配置解析器；旧缓存中已被丢弃的内容须显式重新获取或导入。
- 远程刷新由共享服务串行发布，GPUI 在应用生命周期内检查到期资源；业务草稿或互斥操作期间
  延后。经用户明确选择，健康自有核心运行时只刷新下次启动使用的缓存，不热改当前核心、
  规则、MITM 或 cron 会话，也不自动停核/重启。每批固定请求策略快照与实际自有回流端口；
  证明进程创建身份和监听归属，绕过自有 MITM，不降级显式代理 TLS/认证，不借用外来监听。
  启动时按配置类型保留活动文件输入清单；目标重叠则在请求前整批延后，发布前复核路径及
  所有权，失去自有核心时取消。显式启停与关闭先取消自动任务并等待真实 worker 退出。
  已完成尝试的年龄按资源身份保存在独立元数据中，手动强制刷新也更新年龄；取消与未开始
  的资源不算完成。自动下载有单资源截止时间，必要依赖未完成时不替换完整模块缓存。
  其他壳不因共享接口可用而被宣称接入自动定时。
- 无匹配操作时保留原字节、流、trailer 和错误。匹配正文操作只在明确有界范围内解码和修改；
  不以 lossy UTF-8 或空成功响应隐藏失败。所有盲隧道和 WebSocket 同样遵守已配置的上游路径。
- 未支持的指令/引擎/专有 API 必须明确诊断并不激活，不能静默转成其他网络动作。
  不宣称支持加密容器，也不凭 Surge 近似语法宣称整套 Shadowrocket 语义兼容；后者需要
  可归属的公开契约或授权参考客户端证据。
- 有显式键的持久存储遵守所模拟方言的跨脚本共享语义，模块参数仍按来源隔离；
  旧存储迁移需可恢复，不能把多个内存缓存实例当成一致持久层。
- 只使用自建、公开规范派生或明确许可的验证资源，不执行真实账号业务脚本或把其回声当成兼容证明。

## 实施和验收边界

现有 Tauri/Android 消费者随共享 API 变更迁移，但不借此更换其产品身份。
界面采用现有品牌、语义主题与 GPUI 组件规则，最终通过真实 Windows 窗口验证键盘、IME、
缩放、最小窗口、浅/深色及失败状态，而不是仅提供静态效果图。

系统写入前记录相关基线，恢复仅限可证明本次拥有的效果；异常恢复不能假称绝对多值原子性。
公开发布、推送、替换稳定渠道、删除签名身份和覆盖旧数据不因本次测试授权自动获准。
具体实现、回归、真实 Windows/TLS/安装更新证据及尚缺条件在完成后同步到迁移记录；
本 ADR 不预先宣称这些验收已通过。
