# GPUI 运行状态与核心页

## 修复范围

原状态查询把 `Owned` 与 MITM/辅助会话存在直接判为“需要恢复”，使正常运行也显示异常。
现区分运行资源与恢复义务：运行且正常持有不告警；明确代理冲突始终需恢复；停核后仍有
代理租约、核心、辅助会话、MITM 或任务资源仍需恢复。启停回调与状态轮询共用实现，
不放宽代理归还、后继 owner 或恢复证据的约束。

核心页移除固定描述、空占位与常态指导行，标题和类型/刷新操作保持紧凑；当前核心仅保留
摘要，构建信息进入详情弹窗。最近启动记录移出核心页，阶段开始/完成、耗时、警告、失败
原因和次数写入原应用日志管道，同时覆盖内存与磁盘日志；启动中状态详情仍显示当前阶段。

## 验证与边界

- 定向状态回归：正常运行且持有资源、明确代理冲突、停止后残留及已完成清理。
- 启动日志回归：成功阶段的耗时、警告、失败阶段/原因与重试次数，不把失败阶段记为完成。
- 显式真实核心回归通过 `LANPATH_TEST_SING_BOX` 选择已有二进制，使用临时根、随机回环
  端口和私有 MITM CA；独立构造不含 Windows 系统代理后端/守护的 runtime，避免接触全局
  租约或真实恢复记录。比较正常运行、停核保留资源与完全清理两条状态查询路径。
- `native_core_page_review.ps1` 使用临时根及显式核心夹具，只复制/探测元数据，不启动核心；
  检查默认/最小窗口、150% 缩放、标题/摘要间距、无启动历史、无空状态带及构建详情关闭。
- 本轮不重新进行系统代理接管、TUN 或系统 CA 安装验收，不改已安装程序与用户数据。

## 结果

- Linux 独立桌面项目 fmt、严格 all-target Clippy 和 build 通过；状态测试 3 项、启动日志
  测试 2 项通过。启动日志测试串行保护同组 tracing 调用，避免全局 callsite 注册竞争。
- Windows 原生严格 all-target Clippy、上述 5 项定向测试和 debug build 通过。
  另以已有 sing-box 1.15.0-alpha.13 执行真实核心/私有 MITM 场景：正常运行不需恢复、
  停核保留资源需恢复、完全清理后不需恢复，均通过；未启用系统代理后端或信任私有 CA。
- 原生核心页检查 35 项通过：1180×800、960×640、显式持久化的 150% 缩放，摘要间距、
  标题按钮、无历史/空状态行、构建详情内容及 Escape 关闭。人工复核对应截图通过。
  截图和 UIA 数据位于忽略的 `apps/desktop/target/native-core-page-review/`，不入库。
- Windows 镜像的 `apps/desktop/target/debug/lanpath-gpui.exe` 已更新；安装目录未覆盖。
