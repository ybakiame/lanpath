# ADR-0016：GPUI 统一应用设置与可恢复迁移会话

- 状态：Accepted（仅 GPUI 实验性并行目标）
- 日期：2026-10-31
- 决策来源：用户要求将应用自身设置集中为 TOML，并在旧格式转换和旧备份恢复时提供可复用的开屏迁移流程。

## 背景

GPUI 实验版分别使用 `client.json` 与 `appearance.json`。分散文件不利于人工维护，且直接启动转换无法向用户说明备份、校验和失败结果。备份恢复还可能在窗口出现前替换配置，缺少显式确认和失败返回路径。

Tauri 现行桌面与 Android 继续使用既有 `client.json`。本决策不改变其存储格式、备份协议或启动行为，也不把订阅、规则、脚本和缓存等机器维护文档统一改为 TOML。

## 决定

### 单一实时设置文件

- GPUI 使用 `app.toml` 作为唯一权威应用设置文件，包含 `[client]` 与 `[appearance]`。
- 请求策略、当前订阅、核心选择、端口、系统网络等归 `[client]`；主题、强调色、纯黑和缩放归 `[appearance]`。
- `subscriptions.json`、`profiles.json`、`local_override.json`、`config_slices.json`、脚本和缓存保持 JSON 或原有资源格式。
- 保存一个分区时保留另一分区及无关 TOML 内容和注释。JSON `null` 写为缺席字段，读取沿用既有 Serde 默认值。
- 共享 `ClientConfig` 在 `app.toml` 存在时读写其 `[client]`；否则继续使用 `client.json`，因此 Tauri 默认路径不变。

### 可复用迁移框架

- 版本化迁移集中在 `apps/desktop/src/migration/`。每个迁移实现检测、旧文件声明、转换、校验和产物声明，框架统一负责备份、执行、失败清理和清单。
- 检测到旧设置后，先显示不可操作的迁移页，后台完成备份、转换与校验，成功后才加载业务设置并创建完整主界面。
- 每次迁移在 `backup/migrations/<迁移 ID-UUID>/` 保存 `legacy/`、`converted/` 和 `manifest.json`。备份、转换、校验和清单全部成功后移除原位置旧文件；失败不发布新的权威配置，也不删除原件。已存在 `app.toml` 的遗留目录同样补做备份和清理，且不覆盖有效统一配置。
- 后续版本和配置合并通过新增迁移模块并注册复用该流程，不在启动根目录散布专用逻辑。

### 备份恢复需要确认

- 启动时检测到 `.backup-pending` 后进入恢复确认页，不再在窗口出现前直接应用备份。
- 用户确认后依次执行：校验暂存备份、迁移当前设置、原子恢复、重新加载设置。验证通过前不修改当前配置。
- 恢复到已迁移环境时，旧备份的逻辑 `client.json` 转换为 `app.toml` 的 `[client]`，保留当前 `[appearance]`。恢复事务可以替换旧实时文件，迁移备份与加密恢复前副本仍保留。
- 校验、迁移或恢复失败均显示错误和“返回应用”。用户也可以暂不恢复；待恢复包与当前数据保留，失败返回后继续使用应用。

## 后果

- GPUI 启动增加了明确的两阶段边界：先处理迁移会话，再创建业务页面，避免业务读写与转换竞争。
- 共享备份协议仍保持 v1/v2 兼容，旧加密备份无需重新导出；恢复路径按目标当前格式写入。
- 数据导入、核心选择和代理模式等所有原直接 JSON 读写方必须经过统一设置边界，不能形成第二份实时配置。
- Windows 原生验证必须覆盖旧设置迁移、确认恢复、无效备份失败返回及外观段保留；主机测试不能替代这些窗口行为。
