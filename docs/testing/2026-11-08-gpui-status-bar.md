# GPUI 全局状态栏

## 范围

使用标准 StatusBar 承载窗口级状态与启停，移除原顶部全局运行栏及侧栏底部。
页面标题、分区与工具栏使用释放后的顶部空间。应用版本兼作关于入口，外观与快捷键随迁；
订阅、核心、节点摘要可跳转对应页面。错误与启动限制从运行状态展开查看。

状态仍由原 feature/entity 持有：订阅只读已保存的当前项，核心读取实际选择，节点读取已确认
的组选择并解析嵌套组，独立于列表光标。原有五秒代理快照在核心运行时供页面与状态栏共用，
后台读取不锁命令，内容相同不触发通知，前台选择/模式修改取消旧后台结果；停核后停止查询。
静态 MITM 配置与 CA 的进入页面加载策略保持原样。

## 验证入口与边界

- 独立桌面项目执行 fmt、strict all-target Clippy、节点摘要定向单测及 build。
- 节点摘要回归覆盖嵌套选择、缺少选择、循环、直连和阻断。
- `apps/desktop/tools/native_status_bar_review.ps1` 接收显式 Binary、WindowTools、OutputDirectory，
  使用独立临时数据根。检查底部固定位置、内容/导航边界、各项无重叠、快捷跳转、F6/Shift+F6、
  Tab/Enter、弹层关闭、明暗主题、最小窗口、150% 缩放及长订阅名称。
- 原完整 UI 脚本导航定位改为从内容使用 Shift+F6；本轮仅运行状态栏定向验收，避免重复全量 UI 测试。
- 原生界面检查不启动核心、不接管系统代理、不安装或移除 CA，不改已安装实例的数据。
  不据此宣称真实网络启停或当前旧守护恢复已再次验收。

## 结果

- Linux 与原生 Windows strict all-target Clippy、独立 debug build 均通过；fmt 无差异。
- 节点摘要 3 项定向单测在两端均通过；没有重复运行共享 workspace 或全量页面套件。
- Windows 定向脚本 90 项检查通过，覆盖 1180×800 明暗主题、960×640、最小窗口下的
  150% 缩放及长订阅；底栏与客户区底部、导航/内容与底栏边界按 1 个物理像素容差比较。
  Windows 不可见缩放边框不参与客户区比较。
- F6 正向切换三块区域、Shift+F6 反向、Tab/Enter、快捷跳转、运行详情与快捷键弹窗
  Esc 关闭通过；两类弹窗正文增加显式可访问分组，确认打开后可读取、关闭后移除。
- 两次最终夹具启动均正常退出。截图及无障碍树由脚本保留在指定产物目录，未入库；
  Windows 开发镜像的 debug 程序已更新，已安装程序未覆盖。
