# GPUI 桌面设计

桌面以“准备订阅 → 启动核心 → 选择策略 → 查看连接与流量”为主路径。
本轮只重构实验桌面的呈现与导航，不改变核心、系统网络、证书、数据根或发布边界。

## 窗口与导航

默认窗口 1180 × 800，最小 960 × 640，均为系统逻辑尺寸；界面缩放独立为 75–150%。
侧栏固定 13.5rem，内容使用余下空间；页面以单个区域负责滚动，长表单可滚动，保存操作留在底部。
顶部仅保留窗口标题栏，各页标题与操作位于内容首行；表单字段采用可读宽度，长标识换行或由对应只读编辑器承载。
窗口底部使用标准 StatusBar，跨越导航与内容。窄窗口或高缩放时收起次要版本文字，保留运行状态与启停操作；连接和统计将摘要、
筛选及辅助说明放入受约束的滚动区，为结果列表保留空间。

导航分为工作区（订阅、代理策略、连接、统计）、核心专属配置、工具与扩展（日志、诊断、
脚本、MITM）、设置。配置组跟随实际持久选择，sing-box 展示覆写、结构化配置和预览；
Mihomo 暂时只有预览占位，不展示 sing-box 编辑器。核心页浏览类型不改变实际选择或菜单。
后两组初始折叠；进入目标时自动展开，↑↓、Home/End 只遍历当前核心可见目标，
F6 / Shift+F6 在导航、内容与状态栏间顺逆切换。Ctrl+S 保存当前表单或结构化配置中当前分区，
Ctrl+, 打开外观。外观、快捷键说明与关于迁入状态栏；应用版本按钮兼作关于入口，图标均有可访问名称和悬停提示。
状态栏左侧显示“GPUI 试验版 · 应用版本”，中间显示当前订阅、所选核心及版本、所浏览策略组的确认节点；点击对应项跳转页面。
顶部品牌副标题为“循径而行，径达悠远”，窗口标题使用 Lanpath，实验发行身份保持独立。

入口使用普通滚动容器和标准 SidebarMenuItem，不经过 Sidebar 的虚拟列表；
避免折叠组展开、焦点自动滚动时重试预绘制造成重复无障碍节点。导航视口单独标记无障碍分组，
其边界与实际可操作区域一致，导航延伸至状态栏顶部，不再保留独立底部工具区。

状态栏右侧显示真实运行状态，按状态提供启动、停止或恢复自有控制；启动不可用时提供原因。
点击运行状态展开本地端口、完整错误与恢复原因，长错误不撑高工作区。启停继续使用原有互斥、脏草稿和恢复准入。
订阅摘要来自已保存的当前订阅，独立于列表光标与未保存表单；节点沿核心确认的策略组选择链解析，直连、阻断、待选择与循环明确区分，不将一个组的节点宣称为全部流量出口。

## 表面与主题

颜色集中于 `appearance/theme.rs`；feature 只消费语义颜色。浅色以淡紫灰背景和近白内容表面
分层，深色以中性紫灰背景和稍暗的内容表面分层。普通元数据使用次要文字，强调色只用于选择、
焦点与主要提交；成功、警告、错误保留原有语义。正文默认 text_sm，标题 text_xl，
表格和元数据保持紧凑，间距、字体与控件一同按 rem 缩放。

Root 只绘制一次背景，Windows 11 亚克力优先使用 DWM 系统 Acrylic 背景，旧系统保留框架原生
Blurred 回退；标题栏与侧栏轻度叠色，内容、输入所在表面和弹层维持不透明，避免背景干扰阅读。
实色同时关闭系统背景与原生模糊；纯黑在深色主题强制不透明。其他平台使用实色回退。系统关闭
透明效果、远程桌面或图形驱动可能改变实际材质，不承诺固定的模糊半径；不以假图片模拟系统模糊。

外观页以预览按钮选择跟随系统、浅色、深色，四种强调色提供同名色样；保存成功后立即应用，不显示
常态已保存提示。材质、纯黑与缩放相互独立；恢复 100% 同步实际主题和选择控件。
亚克力背景不透明度支持 20–100%，默认 85%，选择后立即应用。
`[appearance].material` 与 `acrylic_opacity_percent` 只属于本机，缺字段分别回落 acrylic 和 85%，
备份仍只携带主题、强调色和纯黑。
加载失败禁止自动覆盖，修复配置并重启后才允许保存。

## 页面与交互

`design/mod.rs` 统一页面标题、工具栏、设置分区、空状态、流量数字和低优先级说明折叠。
`workspace.rs` 连接标准分段导航和配置编辑表面。组件库继续负责按钮、选择、输入、菜单、
键盘、焦点和弹层；页面 entity 保留草稿、选择、请求与订阅。

sing-box 结构化配置统一收纳网络、DNS、出站、路由与缓存、规则；规则内管理路由规则、
规则集与市场。网络与规则不再作为侧栏独立入口，各 feature entity 继续持有自己的草稿、
保存、重载与校验状态；切换分区不丢弃草稿，无效数值字段修复后才能离开切片编辑器。
高缩放或窄窗口下，结构化配置使用单行紧凑标题，规则常态提示保持简短；错误和脏草稿提示仍完整显示。
网络表单的无障碍分组标记实际滚动视口，不包含底部固定保存区。
分区依据 [sing-box schema](https://sing-box.sagernet.org/schema.json) 的 DNS、入站、出站、
路由与 experimental 归属，范围仍以已实现能力和实际核心校验为准，不声明完整 schema 编辑。

本轮按用户决定只调整界面。sing-box 切片、本地规则和 .srs 仍按 ADR-0017 仅用于 sing-box；
系统网络参数当前仍沿用已有共享持久化及运行时行为，不因菜单分组声称已完成存储隔离。
Mihomo 配置开发时再设计独立存储、读取与校验，避免把 sing-box 模型直接复用为通用模型。
Mihomo 预览入口目前是明确占位，已有后台合成与启停准入维持原行为。

关于页只显示应用版本、OS/架构和程序身份，不读取核心库存或显示目录与权限长说明。

订阅保留编辑、原文、刷新、设为当前四个常用操作，启停可用状态、导出、删除归于“更多”菜单。
菜单打开时重读可用状态，执行前再次核对当前订阅和 busy/locked 状态；删除仍需原有确认，
取消不改变数据。打开编辑器或文件选择的操作带省略号。

连接以三项数值展示快照连接数、累计上传和下载，未加载时显示破折号；统计展示今日上传、
下载和连接数，保留独立查询条件、结果来源和采样说明。数值不作为 TUN、系统代理或全局流量的证明。
查询、采样、配置合成顺序等低优先级说明可展开，危险操作的范围和后果仍留在对应控制与确认中。

设计复查需要真实 Windows 窗口：明暗主题、强调色、纯黑、材质、缩放、最小窗口、导航与键盘、
空状态、错误、草稿和菜单取消。编译与颜色对比度测试不替代真实视觉验收。


## 工作区细化

结构化配置的网络、DNS、出站、路由与缓存、规则均在底部固定保存栏显示“保存配置”、
重载及对应状态，使用同一表面与间距；规则的恢复默认仍是规则专属操作。顶部只承担分区导航。

代理策略分组与节点层级优化：分组使用可横向滚动的 TabBar，路由模式、
组内搜索、原序/名称/延迟排序各成一组；当前使用标识依据核心快照，键盘焦点不冒充实际选择。
“测速所选”与“测速当前组”并列于顶部，组测速为主要操作；页面无手动重新载入入口，在进入页面、核心状态变化、模式或节点选择后同步快照；核心运行时每 5 秒更新同一份代理快照供页面与状态栏共用，忙碌或锁定时暂缓。后台读取不锁用户操作，结果不变不通知页面；前台选择/模式变更取消旧后台结果，停核后取消并停止读取。代理模式持久化到客户端设置并进入合成配置（sing-box 的 Clash API default_mode / Mihomo mode）；默认出站 tag 保持独立含义。重建预览时显示“正在生成并校验”，失败后才提示查看原因，启动准入仍等待校验。
节点按两行展示名称、协议、UDP 与延迟；已测速的超时区别于未测速。筛选与排序只改变视图，
确认操作继续按可见行映射到原始节点名称；自动策略组仍遵循现有只读能力边界。

核心页使用单行标题、类型切换与刷新操作，移除重复的常态提示和空占位行；当前核心只展示
简短选择摘要，Environment、Tags 与可执行文件路径在“构建详情…”展开。最近启动记录归入
应用日志，核心页不再复制展示；日志保留阶段开始/完成、耗时、警告、失败及启动次数。
启动中的当前阶段仍可从全局运行状态详情查看。

全局“需要恢复”区分运行资源与故障：核心运行时持有正常代理/MITM 会话属于正常状态；
明确代理冲突无论核心是否运行都需恢复，停核后仍持有代理或其他资源也需恢复。启停结果与
后台状态轮询使用同一判定，不修改所属恢复、租约或清理策略。

连接页摘要由内容决定高度，窄窗口使用可换行的紧凑摘要；窗口变高时内容起点不随百分比高度下移。
详情编辑器消费标题之外的剩余高度。日志页用分段导航切换内存与磁盘，常用级别筛选和实时刷新
置于独立工具面板，条数与清空放进显示选项菜单；状态在列表下方，采集说明默认折叠。
磁盘日志的筛选、文件/尾部区域、状态和导出分别成组。

脚本远程资源采用卡片列表，明确显示类型、方言、启停状态与更新间隔。新增和编辑使用 modal
表单，保存成功关闭弹窗，取消未保存修改仍需确认；Ctrl+S 支持新建资源。资源保存、缓存更新、
本次运行状态保持不同含义，兼容范围与自动更新规则放入辅助说明，不删除限制与错误提示。

同名目录已经存在的视图统一从 `<feature>_view/mod.rs` 进入，渲染和表单放在目录内按职责拆分；
不同时保留根目录的同名 `.rs`。磁盘日志作为日志视图的子模块收纳。

### 脚本资源 modal 与存储

资源新增/编辑使用标准 Dialog，列表和滚动上下文保留在背景。正文可滚动，保存/取消与校验反馈固定在 footer；Ctrl+S 保存，Esc/关闭/取消统一检查草稿，放弃确认在同一个弹层内完成。取消确认可继续编辑，不叠加第二个 modal。页面只保留“更新资源”和“添加资源…”；内部读写完成后自行同步清单，不暴露重读本地文件的常驻按钮。

更新间隔由正整数与秒/分钟/小时/天下拉组成；打开已有资源时选可整除的最大单位，无损保留特殊秒数，保存时校验秒数换算溢出，列表显示“每 1 天更新”等可读文案。持久层布局与兼容策略见 [ADR-0018](adr/0018-gpui-resource-storage.md)。

本地资源替代一次性配置导入：卡片显示启停和组成数量，新增/编辑使用同一 modal，分为配置片段、关联 JS 与配套图标三个分区。识别脚本引用后可粘贴或从文件读取 JS，未绑定引用不能保存；移除不再引用的 JS 要确认。旧记录缺少原始片段时明确说明，保留既有规则。图标随资源持久保存，远程资源则提供可编辑图标 URL。所有编辑分区共用固定保存/取消栏和 Ctrl+S，关闭草稿需确认。

MITM 以“主机规则 / 请求记录”分区呈现，设置保存固定在底部；不再提供重新载入或刷新状态。
手动补充默认折叠并展示条目数，展开后的草稿跨分区和页面保留；紧凑窗口压缩标题与 CA 摘要，优先保留主机视口。
每次进入页面加载一次已保存设置、资源主机与证书状态，停留期间不轮询这些静态内容。
安装/移除证书使用操作返回值更新信任状态，核心启停只更新运行状态。仅在核心运行且“请求记录”可见时，
每 2 秒读取记录；切换到记录分区时加载一次，结果不变不触发页面通知。
派生主机独立更新，手动主机与启用开关的未保存草稿不被后台结果覆盖。资源更新、参数调整与启停
先影响保存的聚合结果，运行中的 MITM 不热替换，下一次启动生效；主机来自配置片段声明，
不从脚本的 URL 匹配表达式推测。纯 JS 资源不自动绑定 hook 或生成主机声明。

CA 常态仅显示信任状态、安装和移除按钮，路径、指纹、信任范围、所有权回执与 PEM 复制收入
默认折叠的“证书详情”。安装与移除继续使用原确认和所有权校验；进入页面查询不修改系统信任。
