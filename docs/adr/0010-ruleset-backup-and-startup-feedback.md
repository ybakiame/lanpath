# ADR-0010：规则集备份与启动阶段反馈

- 状态：Accepted
- 日期：2026-10-18
- 决策来源：用户报告恢复后首次启动补下载缓慢，要求分析修复或展示配置合成阶段；明确同意将规则集文件纳入备份。

## 根因

v1 备份保存 local_override.json 中的规则集定义及更新时间，不包含 rulesets/ 文件。
跨设备恢复后，启动串行补下载缺失的远程规则集，每个请求超时 60 秒；此前还会下载未被使用的资源。
内置规则集另有镜像回退下载。核心运行状态查询与启动共用 client mutex，不能用它展示启动中的阶段。
文件缺失而更新时间较新时，手动更新的 HEAD 判断也可能错误跳过下载。

## 决定

新导出 manifest 版本为 2，将 rulesets/（builtin、custom 中的内置、远程缓存及手动文件）纳入加密快照、
完整替换事务和恢复前副本。保持 ZIP Deflate 3、age 参数与原大小限制；规则集 JSON 和二进制按字节保存，
不对规则集正文执行路径替换。配置中的托管路径仍重定位。新客户端接受 v1、v2，旧客户端不支持 v2，导入前需升级。
v1 无法补回源设备未备份的文件；恢复后仍按需下载。源设备本来没有文件时，新备份也不能凭空提供离线资源。

journal 显式记录本次事务涉及的根目录；旧 journal 缺少该字段时使用 v1 根列表，避免更新后恢复旧中断事务误删规则集目录。
不引入长期双写或自动扫描/迁移用户数据。

启动补下载只处理启用的路由规则卡片及合成 DNS 规则引用的远程规则集；已有非空文件跳过。
旧备份缺失的手动规则集从配置内嵌正文重建，只补缺失文件、不清理其他文件。
手动更新只有“文件可用且更新时间满足”才智能跳过。下载失败仍沿用原降级策略；不为了提速静默取消有效规则。
不改变请求代理、镜像回退和网络超时策略。

ClientState 的配置准备/核心启动编排拆至 state/start.rs，支持同步阶段回调，原 start() 保持默认无回调行为。
壳层在授权、读取订阅、合成覆写、补齐规则集、启动服务和同步策略时更新短期内存阶段。
proxy_startup_progress 使用独立的小锁，不等待 client mutex；成功、失败或 future 释放时由 guard 清除。
client-core 以唯一 Query key 在共享启动 mutation pending 时每 500 ms 查询；双端仪表盘共用反馈组件。
页面展示实际阶段和规则集 tag，不展示 URL、凭据或虚构百分比；切页后仍可看到当前阶段，结束后隐藏。

## 验收边界

回归覆盖 v2 文件字节完整性及恢复、v1 读取、旧 journal 回滚、缺缓存更新时间跳过、路由/DNS 引用筛选与缓存命中。
浏览器 mock 只验证阶段显示、跨页 busy、失败/成功收尾；真实 Android 网络及 Windows→Android 再次导出导入需设备验收。
